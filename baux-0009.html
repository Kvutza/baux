Run Multiple Regions and Workers

Add baux.regions(count=4) to a search pipeline to maintain four local regions. Use baux.complete(state, ids, y) to return whichever evaluations have finished, and baux.cancel(state, ids) for work you will not complete. Each call returns the next state. The example below also shows how to save and restore it.

1. Multi-Region Search & Asynchronous Evaluation

A region keeps a center, a search length, and a record of recent improvements. Under the TuRBO controller, success and failure counts expand or contract the search length; a sufficiently small region restarts. TuRBO introduced multiple local models with global allocation of evaluations (Eriksson et al. [EPG+19]). In baux, baux.regions configures the regional search, while the pipeline chooses the surrogate and acquisition rule.

Candidate generation perturbs coordinates around a region's center. Incumbent sharing determines whether a result from another region may replace that center: origin_only restricts updates to the originating region, while ellipsoid_ball also admits better observations inside the region's circumscribing ball. This sharing decision is distinct from the choice of surrogate.

Asynchronous workers return results through baux.complete. Each AskId identifies a pending evaluation associated with a region and its generation. Restarting a region invalidates its old pending evaluations; foreign, completed, cancelled or invalidated IDs are rejected. baux.cancel retires unfinished evaluations without adding observations. Historical results can enter separately through baux.import_observations.

2. Deterministic Rollouts & Checkpointing

The functional API returns a new OptimizerState after each transition. Explicit PRNG keys let baux.scan run a fixed sequence and baux.pmap assign a derived key to each branch. Splittable generators are described by Claessen and Pałka [CP13] and Steele et al. [SLF14]. Replaying a search also requires the same objective results and transition order; a seed alone does not make arbitrary asynchronous completion orders equivalent.

baux.freeze serializes optimizer state with a BLAKE3 integrity tag. baux.thaw restores it against a compatible template. The checkpoint does not capture an external evaluator's random generator or worker state. The following example uses a deterministic objective and checks that the restored optimizer produces the same branch digests:

import numpy as np
import baux

bounds = np.tile([-3.0, 3.0], (8, 1))
weights = np.geomspace(1.0, 16.0, 8)


def anisotropic_loss(x):
    return -np.sum(weights * (x - 0.35) ** 2 + 0.1 * np.cos(3.0 * x), axis=1)


pipe = (
    baux.lhd(8)
    | baux.enn(k=6)
    | baux.thompson()
    | baux.regions(count=4, sharing="ellipsoid_ball")
)
s0 = baux.init(bounds, pipe, key=baux.key(101))
s_warm, b_init = baux.ask(s0, num_arms=8)
s_warm = baux.complete(s_warm, b_init.ids, anisotropic_loss(b_init.points))

s_live, b1 = baux.ask(s_warm, num_arms=2)
s_live, b2 = baux.ask(s_live, num_arms=2)
s_live = baux.complete(s_live, [b2.ids[0]], anisotropic_loss(b2.points[:1]))
s_live = baux.cancel(s_live, [b2.ids[1]])
s_live = baux.complete(s_live, b1.ids, anisotropic_loss(b1.points))

blob = baux.freeze(s_live)
restored_a = baux.thaw(s0, blob)
restored_b = baux.thaw(s0, baux.freeze(restored_a))
assert baux.freeze(restored_a) == blob
assert baux.digest(s_live) == baux.digest(restored_a) == baux.digest(restored_b)

rollouts_live = baux.pmap(
    s_live,
    baux.key(77),
    branches=4,
    branch_fn=lambda i, st, k: baux.digest(
        baux.scan(st, k, steps=4, eval_fn=anisotropic_loss, num_arms=2)[0]
    ),
)
rollouts_a = baux.pmap(
    restored_a,
    baux.key(77),
    branches=4,
    branch_fn=lambda i, st, k: baux.digest(
        baux.scan(st, k, steps=4, eval_fn=anisotropic_loss, num_arms=2)[0]
    ),
)
rollouts_b = baux.pmap(
    restored_b,
    baux.key(77),
    branches=4,
    branch_fn=lambda i, st, k: baux.digest(
        baux.scan(st, k, steps=4, eval_fn=anisotropic_loss, num_arms=2)[0]
    ),
)
assert rollouts_live == rollouts_a == rollouts_b and len(set(rollouts_live)) == 4
