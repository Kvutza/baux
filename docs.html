API Reference

Complete interface specifications, mathematical contracts, and runtime guarantees.

v0.0.5 · Python & Rust · ← Return to Monograph

This document defines the formal public API for the baux library across Python 3.12–3.15 and native Rust. All coordinates and candidate bounds follow continuous \([ \text{lower}, \text{upper} ]\) bounding hypercubes. baux models objectives under a maximization contract.

1. Core Optimizer: baux.create_optimizer

The primary factory function for instantiating black box trust-region optimizers: 

create_optimizer(
    bounds: np.ndarray,
    config: Optional[OptimizerConfig] = None,
    rng: Optional[np.random.Generator] = None,
) -> Optimizer
Parameter Type Default Description
bounds np.ndarray required 2D array of shape (D, 2) with float64 row entries [lower, upper]. Must satisfy lower < upper for each dimension.
config OptimizerConfig turbo_enn() Search policy configuration. Built using turbo_enn(), turbo_one(), or turbo_zero().
rng np.random.Generator None Optional seeded NumPy random generator for deterministic candidate generation.
Invariants: Bounds must be finite real numbers. If bounds contain NaNs or infinite bounds, ValueError is raised. Inputs are internally normalized into the unit hypercube \([0, 1]^D\) during search.

2. Optimizer Methods & Properties

The object returned by create_optimizer implements the non-blocking ask / tell interface:

ask(batch_size: int = 1) -> np.ndarray

Proposes a batch of candidate points located inside the active trust region \(\mathcal{TR}_t\).

  • Arguments: batch_size (positive integer, number of trials to sample).
  • Returns: 2D NumPy array of shape (batch_size, D) within parameter bounds.
  • Latency: Evaluated on GPU (Metal MPS or CUDA) when hardware is present; runs sub-millisecond on CPU SIMD fallback.

tell(candidates: np.ndarray, scores: np.ndarray) -> None

Updates the optimizer state with observed evaluations.

  • Arguments:
    • candidates: 2D array of shape (B, D) containing evaluated points.
    • scores: 1D array of shape (B,) containing scalar objective evaluations.
  • Objective: baux maximizes objective scores. To minimize a loss \(f(x)\), pass \(-f(x)\).
  • State Machine: Evaluates whether any point in scores exceeds the incumbent by at least the improvement threshold. Expands or shrinks the trust region side length \(L_t\) accordingly.

Incumbent Properties

  • opt.best_x -> np.ndarray: 1D array of shape (D,) representing the coordinates of the highest-scoring candidate observed thus far.
  • opt.best_y -> float: Scalar float representing the highest score observed.

3. Trust-Region Configurations

Pre-built configuration factories define the search policy and surrogate model:

Factory Function Surrogate Engine Typical Application
turbo_enn() Epistemic Nearest Neighbors Default recommended policy. Non-parametric uncertainty modeling with sub-millisecond proposal latency. Scales to 10,000+ trials.
turbo_one() Gaussian Process (Exact) Single trust region with exact GP kernel inference. Suited for low evaluation counts (< 200 trials).
turbo_zero() None (Model-free) Direct local trust-region perturbation without surrogate fitting. Ideal for noisy or discontinuous functions.

Tunable TuRBO hyperparameters accepted across all configuration builders:

  • length_min: float = 0.5**7 — Minimum trust region side length before triggering a restart.
  • length_max: float = 1.6 — Maximum trust region side length cap.
  • success_tolerance: int = 3 — Consecutive discovery rounds required to trigger trust region expansion (\(L \times 1.5\)).
  • failure_tolerance: int = 5 — Consecutive stagnation rounds tolerated before trust region contraction (\(L \times 0.5\)).
  • batch_size: int = 4 — Default proposal batch size.

4. Epistemic Nearest Neighbors (ENN)

The ENN model provides stand-alone non-parametric regression and posterior uncertainty quantification: 

from baux import ENN
from baux.enn.enn_params import ENNParams
from baux.index import NeighborIndex

# Initialize model with training coordinates (N, D) and targets (N, 1)
model = ENN(train_x, train_y, index_driver=NeighborIndex.FLAT)

# Configure k-NN parameters
params = ENNParams(k_neighbors=8, epistemic_scale=1.0, aleatoric_scale=0.1)

# Compute posterior distribution at query locations (M, D)
post = model.posterior(query_x, params=params)

Posterior Attributes

  • post.mu: np.ndarray — Posterior mean predictions at query coordinates (shape (M, 1)).
  • post.se_epi: np.ndarray — Epistemic standard error reflecting spatial evaluation sparsity (shape (M, 1)).
  • post.se_ale: np.ndarray — Aleatoric noise standard deviation (shape (M, 1)).

posterior_draw(query_x, params=None, function_seeds=None)

Draws continuous sample paths directly from the non-parametric posterior distribution:

  • Arguments: query_x (shape (M, D)), optional params, and function_seeds (list of integers).
  • Returns: (samples, neighbor_indices) where samples is of shape (M, len(function_seeds)).
  • Thompson Sampling: Enables batch acquisition without constructing or factorizing \(N \times N\) covariance matrices.

5. Framework Interoperability

BoTorch Integration (baux.botorch.Model)

Wraps an ENN model as a standard PyTorch / BoTorch surrogate: 

from baux.botorch import Model

model = Model(ENN(train_x, train_y), params=ENNParams(k_neighbors=6))
posterior = model.posterior(torch_test_x)
# Compatible with botorch.acquisition functions

Optuna Integration (baux.optuna.Sampler)

Provides a native search sampler for Optuna hyperparameter optimization: 

import optuna
from baux import turbo_enn
from baux.optuna import Sampler

sampler = Sampler(search_space, config=turbo_enn(), seed=42)
study = optuna.create_study(sampler=sampler, direction="maximize")

6. Hardware Introspection

Query compiled and available hardware execution backends at runtime: 

import baux

for cap in baux.capabilities():
    print(f"{cap.name}: available={cap.available}")
Capability Condition for Activation Execution Mechanism
metal macOS running on Apple Silicon (arm64, M1–M4) Metal Shading Language (MSL) compute shaders with unified memory zero-copy buffers.
cuda Linux with NVIDIA GPU (Compute Capability ≥ 7.5) Custom CUDA C++ kernels utilizing Tensor Cores for batch distance calculations.
simd_cpu Always available on all platforms Pure-Rust AVX-512 (x86_64) and ARM NEON (aarch64) vector instructions.
