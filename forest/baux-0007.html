Function 1. Optimizer Factory: baux.create_optimizer

  • Kvutza

Instantiates an optimization state machine over a bounded continuous domain.

create_optimizer(
    bounds: np.ndarray,
    config: Optional[OptimizerConfig] = None,
    rng: Optional[np.random.Generator] = None,
) -> Optimizer
  • bounds: 2D array of shape (D, 2) defining lower and upper bounds [l_i, u_i] for each parameter dimension.
  • config: Search policy preset: turbo_enn(), turbo_one(), or turbo_zero().
  • rng: Seeded NumPy random generator for deterministic sampling reproducibility.

Context

    Monograph. Baux — Black Box Optimization

    • November 9, 2026
    • Kvutza
    • https://github.com/Kvutza/baux

    baux is a black box optimization library in Python and Rust designed for expensive, derivative-free evaluation loops over continuous and bounded domains. It couples trust-region local search (Algorithm []) with non-parametric Epistemic Nearest Neighbors (Surrogate []) to balance local exploitation and global exploration without incurring the cubic computational bottlenecks of Gaussian Process inference.

    Compute kernels for distance metrics, candidate perturbation, and posterior sampling execute directly on Apple Silicon (Metal MPS) and NVIDIA GPUs (CUDA), backed by an AVX-512 and ARM NEON SIMD pure-Rust CPU engine (Architecture []).

    Lineage. Baseline & Lineage

    • Kvutza

    baux builds on yubo-research/enn (v0.4.1), using its TuRBO trust-region state machine and Epistemic Nearest Neighbors formulation as the algorithmic baseline.

    It extends this baseline with:

    • A single crate: Consolidates ennbo, bpann, and enn-py into a single self-contained baux library and binary wheel (pip install baux).
    • GPU acceleration: Implements Apple Silicon Metal and NVIDIA CUDA compute kernels.
    • Direct interface: Exposes a clean ask/tell loop with native batch proposals.

    Algorithm. Trust-Region Local Search (TuRBO)

    • Kvutza

    High-dimensional black box optimization frequently suffers from the curse of dimensionality when fitting global surrogate models over the entire parameter space. baux confines candidate proposal to a local hypercube &mdash; the trust region &mdash; centered at the current incumbent point \(x^* \in [0, 1]^D\):

    \[ \mathcal {TR}_t = \left \{ x \in [0, 1]^D : \max _{i=1,\dots ,D} \frac {|x_i - x_i^*|}{L_t} \le \frac {1}{2} \right \} \]

    The base side length \(L_t\) adapts dynamically based on observation feedback:

    • Expansion: If consecutive candidate batches improve upon the incumbent, the search volume expands: \(L_{t+1} = \min (L_t \times 1.5,\, L_{\max })\).
    • Contraction: If the optimizer fails to find an improvement across a sequence of failure tolerance rounds (\(\tau _{\text {fail}}\)), the volume contracts: \(L_{t+1} = \max (L_t \times 0.5,\, L_{\min })\).
    • Restart: When \(L_t\) shrinks below \(L_{\min }\), the trust region resets with a new anchor point to prevent asymptotic stagnation in local minima.

    Surrogate. Epistemic Nearest Neighbors (ENN)

    • Kvutza

    Standard Gaussian Process regression requires \(\mathcal {O}(N^3)\) Cholesky factorization of the kernel covariance matrix, creating a computational bottleneck when evaluation counts scale into thousands of trials.

    ENN models function uncertainty through a non-parametric metric projection over the \(k\)-nearest observed points. Posterior uncertainty decomposes into two independent orthogonal fields:

    \[ p(y \mid x, \mathcal {D}) = \mathcal {N}\left (\mu _{\text {post}}(x),\, \sigma _{\text {epi}}^2(x) + \sigma _{\text {ale}}^2\right ) \]
    • Epistemic Uncertainty (\(\sigma _{\text {epi}}\)): Measures spatial evaluation sparsity. Scales proportionally with metric distance to neighboring observations: it vanishes near evaluations and expands in unexplored regions.
    • Aleatoric Uncertainty (\(\sigma _{\text {ale}}\)): Captures irreducible observation noise inherent to stochastic objective evaluations.

    Because ENN evaluates uncertainty via nearest-neighbor distance fields rather than matrix inversion, candidate ranking within the trust region runs in linear time with respect to observed trials, allowing sub-millisecond proposal latency across tens of thousands of evaluations.

    Architecture. Hardware Compute Backends

    • Kvutza

    In high-throughput experimental loops, latency is dominated by host-device memory synchronization. On Apple Silicon, baux leverages Unified Memory Architecture (UMA) via Metal compute pipelines:

    • Observation buffers and trust-region states reside in unified system memory without duplicate host/device allocations.
    • Batch candidate generation, Sobol sequence perturbations, and nearest-neighbor distance sweeps execute directly on Metal shading pipelines.
    • On Linux environments with NVIDIA hardware, custom CUDA kernels handle distance computation and posterior draws across large candidate batches.
    • On systems without GPU support, pure-Rust AVX-512 and ARM NEON SIMD routines provide vectorized CPU fallback.

    Interface. API Specifications & Workflows

    • Kvutza

    The primary Python interface is structured around a non-blocking ask(batch_size) and tell(candidates, scores) loop:

    import numpy as np
from baux import create_optimizer, turbo_enn

# Define parameter domain: continuous bounds for each dimension
bounds = np.array([[-5.0, 5.0], [-5.0, 5.0]])

# Initialize TuRBO optimizer with Epistemic Nearest Neighbors surrogate
opt = create_optimizer(
    bounds=bounds,
    config=turbo_enn(),
    rng=np.random.default_rng(42),
)

# Propose trial batch, evaluate objective, and report back
for step in range(25):
    candidates = opt.ask(batch_size=4)
    scores = -np.sum(candidates**2, axis=1)
    opt.tell(candidates, scores)

print("Incumbent parameters:", opt.best_x)
print("Incumbent reward:", opt.best_y)
