baux

A black box optimization library in Python and Rust.

v0.0.5 · November 2026 · Kvutza Lab · GitHub · PyPI · Crates.io

baux is a black box optimization library designed for expensive, derivative-free evaluation loops over continuous and bounded domains. It couples trust-region local search (TuRBO) with non-parametric Epistemic Nearest Neighbors (ENN) to balance local exploitation and global exploration without incurring the cubic computational bottlenecks of Gaussian Process inference.

Compute kernels for distance metrics, candidate perturbation, and posterior sampling execute directly on Apple Silicon (Metal MPS) and NVIDIA GPUs (CUDA), backed by an AVX-512 and ARM NEON SIMD pure-Rust CPU engine.

1. Baseline & Lineage

baux builds on yubo-research/enn (v0.4.1), using its TuRBO trust-region state machine and Epistemic Nearest Neighbors formulation as the algorithmic baseline.

It extends this baseline with:

  • A single crate: Consolidates ennbo, bpann, and enn-py into a single self-contained baux library and binary wheel (pip install baux).
  • GPU acceleration: Implements Apple Silicon Metal and NVIDIA CUDA compute kernels.
  • Direct interface: Exposes a clean ask/tell loop with native batch proposals.

2. Algorithmic Formulation

Trust-Region Local Search (TuRBO)

High-dimensional black box optimization frequently suffers from the curse of dimensionality when fitting global surrogate models over the entire parameter space. baux confines candidate proposal to a local hypercube — the trust region — centered at the current incumbent point \(x^* \in [0, 1]^D\): 

TR_t = { x in [0, 1]^D : max_i |x_i - x_i^*| / L_t ≤ 1/2 }

The base side length \(L_t\) adapts dynamically based on observation feedback:

  • Expansion: If consecutive candidate batches improve upon the incumbent, the search volume expands: \(L_{t+1} = \min(L_t \times 1.5,\, L_{\max})\).
  • Contraction: If the optimizer fails to find an improvement across a sequence of failure tolerance rounds (\(\tau_{\text{fail}}\)), the volume contracts: \(L_{t+1} = \max(L_t \times 0.5,\, L_{\min})\).
  • Restart: When \(L_t\) shrinks below \(L_{\min}\), the trust region resets with a new anchor point to prevent asymptotic stagnation in local minima.

Epistemic Nearest Neighbors (ENN)

Standard Gaussian Process regression requires \(\mathcal{O}(N^3)\) Cholesky factorization of the kernel covariance matrix, creating a computational bottleneck when evaluation counts grow into thousands of trials.

ENN models function uncertainty through a non-parametric metric projection over the \(k\)-nearest observed points. Posterior uncertainty decomposes into two independent orthogonal fields:

  • Epistemic Uncertainty (\(\sigma_{\text{epi}}\)): Measures the sparsity of evaluations in the local metric space. Epistemic uncertainty scales proportionally with distance to neighboring observations: it vanishes in densely sampled domains and expands in unexplored regions.
  • Aleatoric Uncertainty (\(\sigma_{\text{ale}}\)): Captures irreducible evaluation noise inherent to stochastic objective evaluations.
Computational Advantage: Because ENN evaluates uncertainty via nearest-neighbor distance fields rather than matrix inversion, candidate ranking within the trust region runs in linear time with respect to observed trials, allowing sub-millisecond proposal latency across tens of thousands of evaluations.

Resident GPU Execution Pipeline

In high-throughput experimental loops, latency is dominated by host-device memory synchronization. On Apple Silicon, baux leverages Unified Memory Architecture (UMA) via Metal compute pipelines:

  • Observation buffers and trust-region states reside in unified system memory without duplicate host/device allocations.
  • Batch candidate generation, Sobol sequence perturbations, and nearest-neighbor distance sweeps execute on Metal shading pipelines.
  • On Linux environments with NVIDIA hardware, custom CUDA kernels handle distance computation and posterior draws across large candidate batches.

3. Code Specimens & Workflows

The primary Python interface is structured around a non-blocking ask(batch_size) and tell(candidates, scores) loop. Select a workflow below: 

import numpy as np
from baux import create_optimizer, turbo_enn

# Define parameter domain: continuous bounds for each dimension
bounds = np.array([[-5.0, 5.0], [-5.0, 5.0]])

# Initialize TuRBO optimizer with Epistemic Nearest Neighbors surrogate
opt = create_optimizer(
    bounds=bounds,
    config=turbo_enn(),
    rng=np.random.default_rng(42),
)

# Optimization loop: propose batches, evaluate, and report scores
for step in range(25):
    # 1. Ask for a batch of candidate trial vectors
    candidates = opt.ask(batch_size=4)

    # 2. Evaluate objective (baux maximizes rewards; negate for minimization)
    scores = -np.sum(candidates**2, axis=1)

    # 3. Tell observations back to the optimizer
    opt.tell(candidates, scores)

print("Incumbent parameters:", opt.best_x)
print("Incumbent reward:", opt.best_y)
import numpy as np
from baux import ENN
from baux.enn.enn_params import ENNParams
from baux.index import NeighborIndex

# Train surrogate on evaluated points (train_x: NxD, train_y: Nx1)
model = ENN(train_x, train_y, index_driver=NeighborIndex.FLAT)

# Query posterior distribution with calibrated k-NN parameters
params = ENNParams(k_neighbors=8, epistemic_scale=1.0, aleatoric_scale=0.1)
post = model.posterior(query_x, params=params)

print("Posterior mean:", post.mu)
print("Epistemic uncertainty (spatial sparsity):", post.se_epi)
print("Aleatoric uncertainty (measurement noise):", post.se_ale)

# Draw continuous non-parametric posterior sample functions
samples, indices = model.posterior_draw(query_x, params=params, function_seeds=[42])
import torch
import numpy as np
from baux import ENN
from baux.botorch import Model
from baux.enn.enn_params import ENNParams

# Wrap an ENN surrogate model as a BoTorch-compatible Model
train_x = np.random.normal(size=(24, 4))
train_y = np.cos(train_x[:, :1])
model = Model(ENN(train_x, train_y), ENNParams(k_neighbors=6))

# Interoperate with BoTorch acquisition functions
test_x = torch.randn(5, 4, dtype=torch.double)
posterior = model.posterior(test_x)
print("Mean:", posterior.mean)
print("Variance:", posterior.variance)
import optuna
from baux import turbo_enn
from baux.optuna import Sampler
from optuna.distributions import FloatDistribution

search_space = {
    "learning_rate": FloatDistribution(1e-4, 1e-1, log=True),
    "weight_decay": FloatDistribution(1e-6, 1e-2, log=True),
}
sampler = Sampler(search_space, config=turbo_enn(), seed=42)

def objective(trial):
    lr = trial.suggest_float("learning_rate", 1e-4, 1e-1, log=True)
    wd = trial.suggest_float("weight_decay", 1e-6, 1e-2, log=True)
    return -( (lr - 0.01)**2 + (wd - 0.001)**2 )

study = optuna.create_study(sampler=sampler, direction="maximize")
study.optimize(objective, n_trials=40)
print("Optimized parameters:", study.best_params)
