Readout inequivalence witness
----------------------------
Hold the hidden state h fixed and nonzero, and set the 64-column query projection
Q to zero. The hierarchical query q = sqrt(8) Q^T h is zero. Every hierarchy
logit is zero, so L_tree = 6 log(8) = log(262144), independent of readout W.
Its partial derivative with respect to W at fixed h and Q is zero.

For the flat readout, let h be a coordinate vector and let W in that coordinate
be a at the target token and zero at all other tokens. Then
  L_flat(a) = log(exp(a) + V - 1) - a,
  d L_flat / da = exp(a)/(exp(a) + V - 1) - 1.
At a = 0 the derivative is 1/V - 1, which is nonzero for V > 1. Thus the two
readouts are not the same function, even though both losses equal log(V) at
a = 0. Matching an initial scalar loss would not establish gradient parity.
This is a readout-level witness, not a claim about a complete model trajectory.

Additional objective discrepancy
--------------------------------
ObjectiveFunction::token_loss defines bounded-log-likelihood as log(2 - p).
The hierarchical Metal kernel applies that transformation separately at each
of six levels, giving sum_l log(2 - p_l), rather than log(2 - product_l p_l).
For p_l = 1/8 these are 6 log(15/8) and log(2 - 8^-6), respectively.
GenerationReward::BoundedCrossEntropy instead computes exp(-mean NLL).
None of these three expressions can be silently substituted for another.
The target comparison should use cross-entropy until bounded semantics are
resolved independently.

Smooth readout derivative
-------------------------
For each visited parent, let S_c be the leaves below child c and m_c = |S_c|.
Write C_c = sum_{v in S_c} W_v / sqrt(m_c), q = sqrt(8) Q^T h,
z_c = dot(q, C_c), and e_c = softmax(z)_c - indicator(c = target child).
For one target, summed over the visited parents:
  g_q = sum_c e_c C_c
  g_W_v = sum_{c: v in S_c} e_c q / sqrt(m_c)
  g_Q = sqrt(8) h g_q^T
  g_h = sqrt(8) Q g_q.
At the final level m_c = 1, so the same formula includes leaf readouts.
For a mean over N target positions, sum these adjoints and divide by N.
Q shares storage with core QKV parameters, and W with input embeddings: the
core/embedding adjoints must be added to these readout contributions.

research/readout.py evaluates the forward loss by direct leaf-range summation.
Its backward uses range endpoint updates followed by prefix sums to distribute
centroid adjoints. The forward and backward therefore use different accumulation
paths. The derivative is dense in W in general: at the root the child ranges
partition the whole vocabulary. O(log V) target scoring does not imply an
O(log V) full tied-parameter gradient or Muon update.

Metal readout qualification
--------------------------
Command: ./tools/buck2w build --console simple //research:readout-metal
Host: Apple M4. Captured output: research/readout.txt.
The Buck target compiles the actual fbt_wave.metal forward source together with
rust/crates/baux/src/fbt_readout/grad.metal. The Swift host mirrors the 32-byte
WaveShape ABI and
disables fast math; this does not yet exercise the production Rust dispatch.
It compares production losses and prototype gradients against a double-precision
CPU reference at the full width 512, query size 64, and vocabulary 262144.

Contract: query and centroid half casts use identity adjoints. CPU query values
are rounded to half after the ordered Float projection. CPU centroids are
independently computed from stored half readout weights; accessed centroids may
differ by at most one half ULP (observed discrepancy was zero). Gradient
references then use the actual rounded GPU centroids. Thus this is a
straight-through backward evaluated at rounded primals, not a derivative of
the literal rounded program. Loss/gradient tolerance is
3e-6 * (1 + abs(reference)); this is an empirical test tolerance.

Six fixtures cover one, two, three and 32 targets, extreme token IDs, hierarchy
boundaries, repeated targets, and a zero query projection. All 102658314 checked
values passed; maximum absolute discrepancy was 1.921e-6. Every one of the
64*262144 readout adjoints and 512*640 projection adjoints is compared, including
projection columns outside the query slice which must receive zero contribution.
These are finite fixtures, not a proof over all weights or inputs.

The prototype accumulates target contributions into shared hierarchy-node
adjoints, then gathers each leaf's six ancestor contributions. This avoids a
token-count times vocabulary-size loop. Node adjoints must be cleared once per
batch, and target coefficients are divided by the number of targets exactly
once. Atomic sums can vary with execution order. The implementation now has a
production Rust dispatcher in fbt_readout.rs. Its contributions are additive;
callers clear complete gradients once before the backward pass. There is no
throughput claim.

Still required: qualify routing and recurrent-core derivatives on fixed corpus
tokens, then run stateful Muon and Baux with common initialization and held-out
measurement.

Shared-gradient integration
---------------------------
The Rust shared_gradients fixture dispatches the production readout forward and
adjoint with QKV/readout slices at nonzero offsets in one gradient buffer. It
seeds all gradients with 0.125, executes a readout pass, actual dense/embedding
backward kernels, and a second readout pass. Independent analytic expectations
check affected entries, untouched dimensions and guard regions. It also checks
that dense input gradients preserve their seeded values.

This exposed a production error in fbt_train_grad.metal. Both tensor-op dense
gradients loaded their prior destination, but matmul2d_descriptor defaults to
mode::multiply. Thus op.run discarded that value. The projection witness was
-0.0765388 instead of -0.028077615305021147; the missing amount was the seeded
gradient plus the first readout contribution. Loading the destination alone
does not request accumulation. Both descriptors now explicitly select
mode::multiply_accumulate, matching the scalar kernels' += behavior. This also
matters for recurrent visits sharing a physical layer's weights.

Packed attention adjoint
------------------------
The next source audit and analytic GPU probe exposed another production error.
reverse_attention passed the beginning of its packed QKV buffer as both query
and KV, and similarly passed the beginning of the packed gradient as both query
and KV adjoints. The sparse-attention backward kernel expects KV to begin at
the key slice. Forward stores queries in columns 0..512, keys in 512..576 and
values in 576..640. Consequently backward read the wrong keys/values and wrote
their adjoints into query columns. Query/KV strides of 640 do not repair a
missing within-row base offset.

Pisa1::backward now accepts one packed primal and one packed adjoint, owns the
1024-byte half / 2048-byte float KV offsets, and checks slice extents. The sole
training caller uses this interface. The one-token analytic witness failed
before the fix (query gradients changed even though attention probability was
one), then passed. The final regression uses two causal tokens with keys zero,
values +1/-1 and eight unit output adjoints. It checks key adjoints +/-1/2,
value adjoints 4, zero query contributions, nonzero buffer offsets, seeded
accumulation and untouched guards.

Whole-model secants and routing
-------------------------------
The opt-in BAUX_CORPUS_DIRECTIONS diagnostic measures actual plus/minus losses
against the baseline gradient dotted with the actual rounded parameter change.
It uses gradient-sign directions scaled by family weight RMS, restores all
changed parameters after each score, and samples three step fractions in eleven
parameter families. Full output, source hashes and reproduction command are in
research/directions.txt. A successful diagnostic process is not a gradient
accuracy pass; every directional record is explicitly diagnostic_only=true.

After the attention offset fix, final_norm observed/predicted ratios are
0.99979..0.99997, with unchanged final-layer selections. At fraction 1/128 the
query ratio is about 0.779, while its final-layer attention sets differ on
3036/3047 tokens and expert sets on 2825/2751 tokens (minus/plus). The router
ratio is about 9.207, with expert-set changes on 2705/2654 of 4096 tokens. These
counts ignore order and inspect only the final execution; they do not certify
the rest of the recurrent trajectory. Predictor secants can even disagree in
sign. Before/after runs use their respective gradient-sign directions, so they
are not a controlled same-direction ablation.

Thus these probes cross discrete selection boundaries, whereas the implemented
pathwise backward holds selected blocks/experts fixed and uses identity cast
adjoints. Literal finite secants also include quantization. Neither the observed
discrepancy nor the existence of route changes alone establishes that the
remaining conditional gradients are correct or incorrect. Qualify the selected
smooth subgraphs independently before interpreting a whole-model comparison.
In particular, a global smoothness/Taylor-decrease premise cannot simply be
imported from the continuous readout into this hard-routed model.

Research hypothesis, not a finding: Baux might gain per round by modeling loss
changes across selection boundaries that a pathwise gradient misses. A useful
falsification compares matched Baux/Muon losses with route-change measurements
and a common fixed-selection ablation. Route switches alone do not demonstrate
an optimizer advantage, and derivative bugs must not be used to weaken Muon.

Selected router adjoint
------------------------
Forward stores half logits, selects three experts and computes
  s_j = max(sigmoid(logit_j), 1e-20), p_j = s_j / sum_k s_k,
then casts p_j to half. With selection fixed and identity cast adjoints,
  dlogit_j = (g_j - sum_k g_k p_k) * s'_j / sum_k s_k,
where s'_j is zero on the floor branch. This derivative uses the unrounded
probabilities at the saved half logits. The half weights are appropriate for
the subsequent expert-output gather's derivative, but cannot reconstruct the
normalizer that preceded their cast.

The former backward recomputed logits from input/router weights without the
forward half cast, then used rounded p_j in both the weighted center and a
reconstructed denominator. It also omitted the sigmoid floor's derivative.
At three zero logits and three unit upstream adjoints, the normalized-sigmoid
precursor is constant one, yet the GPU returned 0.00004068017 instead of zero.
This regression failed before the fix. Backward now reads saved logits and
recomputes their clamped sigmoid normalization before rounding. It removes
the redundant router dot products and follows the forward floor branch.

Four GPU fixtures pass against independent f64 finite differences at three
steps (absolute tolerance 2e-7): equal logits/unit adjoints, unequal logits,
all logits below the sigmoid floor, and positive saturation. The fixtures also
check actual production forward route weights. This qualifies the selected
normalization subgraph, not the discrete top-three selection or every MoE
projection/packing/accumulation path.

Stateful fixed-corpus path
--------------------------
An explicit objective.window-tokens=4096 now selects fbt_moe/matrix.rs for Muon
or AdamW, rather than lowering that request to generated continuations. This
path currently requires the MHC4 model, cross-entropy and one fully scored,
unchunked context. Existing recipes without a window retain their generated
path. Nineteen configuration tests, including that distinction, pass.

The matrix session initializes the same CandidateWeights function and model
seed as Baux, calls the same CorpusSet causal_batch with reference_seed and
round zero, then retains one Trainer and Optimizer across all rounds. Each
round owns forward/backward, update and a separate post-update score. Exposure
counts one training window; scorer-work counts both passes. No corpus-epoch
claim is made. long::validate is shared by both paths, including its fixed
per-source windows and mixture weights. Both now evaluate validation at round
zero; the former round-zero branch required interval=0, which validation rejects.

Matrix run artifacts identify the optimizer and stateful fixed-corpus protocol
instead of emitting BO surrogate/acceptance metadata. Tensor-update statistics
are explicitly unavailable for this path. The configured Muon uses the existing
five-step polar polynomial, matrix learning rate 0.02 and momentum 0.95, with
the existing AdamW settings for embeddings, norms, biases and controls. This
is a baseline implementation, not a hyperparameter-optimality claim.
